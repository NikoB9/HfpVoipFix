# HfpVoipLab 1.7.20

D4 remains a four-phase diagnostic experiment. It now uses the same microphone configuration as validated standalone D3: source MIC, policy-selected built-in microphone, latched actual device ID, and the existing voice communication SCO playback attributes/gain. It does not force the bottom microphone or request the VOICE_COMMUNICATION capture profile. D2/D3 PCM configurations remain unchanged.

The prior complete 1.7.19 report showed the vendor primary output following SCO playback, closing the speaker path during phase 3 and reopening it after phase 4 began. The subsequent report preserved phase 1 but lacked subsequent phase markers. The missing logs do not establish that those phases never ran, and neither report proves what was audible. The source change is not a confirmed remedy for the vendor output-sharing conflict.

The experimental-strategy acknowledgement checkbox and manual bridge arm button are removed. Choose/apply a mode outside a call, start capture, and wait for D2/D3/D4 ready. Capture owns automatic preparation: a fresh matching idle Bluetooth module, clean state, required hooks and microphone permission remain mandatory. It does not open audio until the live call/SCO handshake is ready. The call button waits briefly for automatic readiness. After a completed call the next idle call can be prepared automatically within the same capture. It never attaches a new bridge mid-call, including after the 60-second D4 sequence ends.

Stop bridge suspends automatic preparation until mode application or a new capture. Finishing capture stops the bridge before exporting. Errors also suspend automatic preparation instead of repeatedly restarting a failing path. Mode changes close an idle prepared bridge first; mode changes during an active call remain rejected. Android's microphone permission prompt remains required.

A bounded, sanitized bridge-events.log now records bridge metadata directly to an app-private file before sending it to logcat; export includes it independently of hfp-events.log. It records phase transitions, route IDs, counts, RMS and lifecycle events, never PCM. Phase-based audio policy/flinger snapshots remain included when those markers reach logcat. Host tests cover idle-only automatic preparation, stop/permission/stale/dirty state rejection, independent-journal redaction/size limit and ZIP preservation.

Install, reboot once for LSPosed, choose D4, apply, start capture and call after D4 ready. Keep the call at least 65 seconds. Four 15-second phases are RX only, RX plus MIC capture, full duplex, TX stopped with MIC capture retained. Microphone audio is transmitted only in phase 3. Note received sound per phase and ask the correspondent about microphone only in phase 3. Hang up, finish capture and export. This release has no hardware audio validation before the user's test.
